# Рецепт v5 — Deep-Taper из FP8 источника

Дата: 2026-03-22

---

## Цель

Пробить потолок PPL ~9.4 (ограничение двойной квантизации Q8_0) за счёт квантизации напрямую из FP8 оригинала.

---

## Источник

**FP8 оригинал**: `MiniMaxAI/MiniMax-M2.5` (~320 GiB, 126 safetensor-шардов)

Путь: FP8 → `convert_hf_to_gguf.py` (деквант в BF16) → GGUF → `llama-quantize` → v5

Альтернатива: `PrimeIntellect/MiniMax-M2.5-bf16` (~619 GiB, уже деквантирован в BF16)

## Рецепт: две конфигурации

### v5-Compact (~92 GiB, in-RAM на 96 GB)

Tapered-RAM рецепт, но из FP8/BF16 источника. Для daily-driver.

```
Edge      [0-1, 60-61]   (4):  down=iq5_k,  gate=iq4_xs,  up=iq4_xs
Bridge    [2-4, 57-59]   (6):  down=iq4_xs,  gate=iq3_ks,  up=iq3_ks
Core      [5-56]         (52): down=iq3_ks,  gate=iq3_ks,  up=iq3_ks

Attention:  attn_q=iq5_k, attn_k/v=q8_0, attn_output=q5_K
Embeddings: q8_0, Output: q8_0, Router: f32
```

Ожидаемый BPW: ~3.5
Ожидаемый PPL: **~9.0–9.4** (vs 9.70 из Q8_0)
Скорость: ~4 t/s (in-RAM)

### v5-Quality (~114 GiB, swap-bound на 96 GB)

Deep-Taper рецепт с улучшенным gate/up разделением. Максимум качества.

```
Edge      [0-3, 58-61]   (8):  down=iq5_k,  gate=iq5_k,   up=iq4_xs
Bridge    [4-7, 54-57]   (8):  down=iq5_k,  gate=iq4_xs,  up=iq4_xs
Mid-sens  [8-13, 48-53]  (12): down=iq5_k,  gate=iq4_xs,  up=iq3_ks
Mid-high  [14-17, 44-47] (8):  down=iq5_k,  gate=iq3_ks,  up=iq3_ks
Core      [18-43]        (26): down=iq4_xs,  gate=iq3_ks,  up=iq3_ks

Attention:  attn_q=iq5_k, attn_k/v=q8_0, attn_output=q5_K
Embeddings: q8_0, Output: q8_0, Router: f32
```

Ожидаемый BPW: ~4.3
Ожидаемый PPL: **~8.9–9.2** (vs 9.42 из Q8_0)
Скорость: ~4 t/s (с swap ~19 GiB, после прогрева)

## Изменения по сравнению с v4

### 1. Источник: FP8 вместо Q8_0

Главное изменение. Устраняет промежуточную Q8_0 квантизацию.

Ожидаемый эффект: **-0.3 — -0.5 PPL**

### 2. Асимметрия gate vs up (v5-Quality)

В v4 gate и up квантовались одинаково. В v5-Quality:
- **gate** (фильтр, решает что пропустить) — точнее
- **up** (расширение) — на один шаг агрессивнее

Пример для edge: gate=iq5_k, up=iq4_xs (в v4 было оба iq5_k).

Логика: gate контролирует информационный поток. Ошибка в gate отфильтровывает нужное или пропускает лишнее. Ошибка в up менее критична — down-проекция частично компенсирует.

Эффект на размер: экономия ~2-4 GiB (edge+bridge up понижены), перераспределены на mid-sens.

Ожидаемый эффект на PPL: **-0.0 — -0.1** (скромно, но бесплатно)

### 3. Imatrix

Использовать `D:\imatrix_minimax_m25_bf16.dat` (ubergarm, из BF16, 497 entries, 796 chunks).

При квантизации из FP8/BF16 imatrix совпадает с распределением весов — это **правильное** использование (в отличие от v3.1/v4, где imatrix от BF16 применялся к Q8_0).

## Процесс квантизации

### Шаг 1: Конвертация FP8 → GGUF (BF16)

```bash
python convert_hf_to_gguf.py \
    --outtype bf16 \
    --outfile "D:/MiniMax-M2.5-BF16.gguf" \
    "путь/к/MiniMaxAI/MiniMax-M2.5"
```

Нужно: ~320 GiB для скачивания FP8 + ~450 GiB для BF16 GGUF = **~770 GiB** свободного места.

Или потоковый вариант: скачивать шарды по одному, конвертировать, удалять.

### Шаг 2: Квантизация

```bash
llama-quantize \
    --imatrix "D:/imatrix_minimax_m25_bf16.dat" \
    --output-tensor-type q8_0 \
    --token-embedding-type q8_0 \
    --attn-q-type iq5_k \
    --attn-k-type q8_0 \
    --attn-v-type q8_0 \
    --attn-output-type q5_K \
    --ffn-gate-inp-type f32 \
    --custom-q "..." \
    "D:/MiniMax-M2.5-BF16.gguf" \
    "D:/MiniMax-M2.5-v5-Quality.gguf" \
    IQ3_KS
```

Без `--allow-requantize` — источник BF16, не нужно.

### Шаг 3: Верификация

- Проверить BPW и размер
- Замерить PPL (полный wikitext-2)
- Сравнить с v4 PPL (9.42)
- Прогнать Eval Suite (13 тестов)

## Эксперимент: Taper vs Uniform (2026-03-22)

### Гипотеза

PPL 9.42 при 4.26 bpw — аномально высокий по сравнению с ожидаемым для Q4_K_M (~5–6.5 при 4.8 bpw). Возможная причина — 68 тензоров в iq3_ks (3.19 bpw) являются "слабым звеном", которое тянет PPL вниз непропорционально своей доле.

### Ключевое наблюдение

Uniform iq4_xs для ВСЕХ экспертов = **114.5 GiB** — почти идентично v4 (114 GiB). Но без "слабого звена":

- v4: edge/bridge/mid-sens down в iq5_k (хорошо), core gate/up в iq3_ks (плохо) → **средне**
- Uniform: все эксперты в iq4_xs → **ровно**

### Варианты для тестирования

```
Вариант D — Uniform iq4_xs (~114 GiB)
  Все 186 expert тензоров = iq4_xs
  Нет зон, нет taper, нет асимметрии down/gate/up
  BPW: 4.30
  Swap: ~19 GiB
  Проверяет: лучше ли ровный bpw, чем taper с iq3_ks?

Вариант A — Все iq3→iq4 (~124 GiB)
  Текущий v4, но все 68 iq3_ks заменены на iq4_xs
  Сохраняет taper (edge/bridge down = iq5_k)
  BPW: 4.66
  Swap: ~29 GiB
  Проверяет: насколько iq3_ks тянет PPL вниз?

Вариант B — Core gate/up iq3→iq4 (~122 GiB)
  Только 52 core gate/up тензора: iq3_ks → iq4_xs
  Mid-high gate/up остаётся iq3_ks (16 тензоров)
  BPW: 4.57
  Swap: ~27 GiB
  Проверяет: достаточно ли поднять только core?

Вариант C — Полный апгрейд iq3→iq4 + iq4→iq5 (~136 GiB)
  Все iq3→iq4, все iq4→iq5
  BPW: 5.10
  Swap: ~41 GiB
  Проверяет: потолок качества при нашей методологии
```

### Порядок экспериментов

```
1. Вариант D (uniform iq4_xs) — бесплатный по размеру, быстрая проверка гипотезы
   → Если PPL D < PPL v4: iq3_ks было "слабым звеном", taper не помогал
   → Если PPL D > PPL v4: taper действительно ценен, iq5_k на edge важен

2. Вариант A (все iq3→iq4) — если D подтвердил, что iq3 = проблема
   → Показывает чистый выигрыш от убирания iq3_ks при сохранении taper

3. Результаты определят стратегию v5:
   → Если uniform лучше: v5 = uniform iq4_xs + FP8 источник
   → Если taper лучше: v5 = taper без iq3_ks (A/B) + FP8 источник
```

### Фундаментальный вопрос

**Что важнее для PPL: отсутствие "слабого звена" или точность edge-слоёв?**

Зонный taper основан на предпосылке "edge-слои чувствительнее". Но если iq3_ks core gate/up вносят больше ошибки, чем iq5_k edge экономит — taper проигрывает uniform.

Этот эксперимент ответит на вопрос и определит стратегию всей серии квантизаций.
