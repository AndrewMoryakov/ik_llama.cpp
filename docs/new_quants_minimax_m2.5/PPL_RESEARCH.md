## 2. Ключевые выводы

### Вывод 1: PPL ~9.7 — это потолок для 3.4 bpw из Q8_0

Исправление attention (iq3_ks → q8_0) и добавление imatrix **не дали ожидаемого улучшения**. PPL v3.1 (9.70 ± 0.08) практически идентичен грубой оценке v2 (9.53 ± 0.66, с учётом погрешности). Это значит:

- Attention — малая доля (~3%) модели, его качество слабо влияет на PPL
- Expert FFN в iq3_ks — это 95% весов и доминирующий источник ошибки
- Именно bpw экспертов определяет PPL, а не attention или embeddings

### Вывод 2: Расчётные оценки PPL были оптимистичны

Оценки ~8.72 из рецептов, вероятно, предполагали квантизацию из BF16 с оптимальным imatrix. Наш путь (Q8_0 → iq3_ks) даёт ~9.7 — на ~1 пункт хуже. Это существенная разница.

### Вывод 3: Imatrix от BF16 может не помогать при Q8_0 источнике

Imatrix рассчитан на распределение весов BF16. При квантизации из Q8_0 веса уже деформированы — imatrix может давать неточные приоритеты. Нужен imatrix, сгенерированный непосредственно из Q8_0.

### Вывод 4: Бюджет байтов потрачен не оптимально

В v3.1 мы потратили ~1.4 GiB на апгрейд attention и embeddings до q8_0. Этот бюджет дал прирост BPW (+0.09), но **не снизил PPL**. Те же 1.4 GiB, потраченные на апгрейд ~9 слоёв core down_exps с iq3_ks до iq4_xs, вероятно дали бы больший эффект на PPL — потому что эксперты это 95% модели.

## 3. Направления снижения PPL (v4)

### 3.1. Квантизация из BF16 напрямую [высокий приоритет]

**Суть:** Убрать двойную квантизацию (BF16→Q8_0→iq3_ks). Прямой путь BF16→iq3_ks устраняет промежуточную потерю.

**Ожидаемый эффект:** ~0.5–1.0 пункт PPL (с 9.7 до ~8.7–9.2). Это приблизит нас к расчётным оценкам.

**Стоимость:** Скачать BF16 MiniMax M2.5 (~619 GiB safetensors). Нужно ~500+ GiB свободного места для конвертации.

**Источник найден:** `PrimeIntellect/MiniMax-M2.5-bf16` (125 шардов, 619 GiB). Это деквантизация FP8→BF16, не оригинальные обучающие веса, но значительно лучше Q8_0 как источник.

**Блокер:** Дисковое пространство. Детальный анализ: `HYBRID_SOURCE_RESEARCH.md`.

### 3.2. Перераспределение бюджета: attention↓, experts↑ [высокий приоритет]

**Суть:** Вместо attention q8_0 (дорого, мало эффекта на PPL) — опустить attn_q до iq5_k, а освободившиеся ~0.5 GiB потратить на апгрейд 3 слоёв sensitive-middle down_exps с iq3_ks до iq4_xs.

**Ожидаемый эффект:** PPL чуть ниже при том же размере файла.

**Стоимость:** Переквантизация (~1 час). Размер не меняется.

### 3.3. Генерация своего imatrix из Q8_0 [средний приоритет]

**Суть:** Запустить `llama-imatrix` на Q8_0 источнике с калибровочным текстом, получить imatrix, точно соответствующий распределению весов, из которых мы квантуем.

**Ожидаемый эффект:** Неизвестен (может быть малый, может быть средний).

**Стоимость:** Генерация imatrix на 228B модели — это часы-сутки. Нужен калибровочный текст.

### 3.4. Альтернативные IQ-типы для core [средний приоритет]

**Суть:** Попробовать вместо iq3_ks:
- `iq4_kss` (4.0 bpw) — более высокий BPW, но другой алгоритм
- `iq4_kt` (4.0 bpw, trellis) — новый тип, потенциально лучший quality/bpw
- `iq3_k` (3.0 bpw) — другая внутренняя структура

**Ожидаемый эффект:** Зависит от типа. iq4_kss/iq4_kt не влезут в 95 GiB для всех core-слоёв.

**Стоимость:** Переквантизация на каждый вариант.

### 3.5. Selective expert upgrade в пределах бюджета [средний приоритет]

**Суть:** У нас ~2.5 GiB свободного бюджета (95 - 92 - 0.5 KV). Каждый апгрейд down_exps iq3_ks → iq4_xs стоит ~152 MiB. На 2.5 GiB можно поднять ~16 тензоров = ~5 слоёв down_exps.

Какие слои поднимать? Два подхода:
- **Sensitive-middle** (слои 5–10, 51–56) — по аналогии с рецептом E
- **По данным imatrix** — поднять слои с наибольшей importance

**Ожидаемый эффект:** Малый–средний (~0.1–0.3 PPL).

**Стоимость:** Переквантизация.

### 3.6. Перебалансировка зон [малый приоритет]

**Суть:** Текущий Tapered-RAM: 4 edge + 6 bridge + 52 core. Эмпирически подобранные границы. С данными per-layer sensitivity можно оптимизировать.

**Ожидаемый эффект:** Малый.

### 3.7. Увеличение RAM [радикальный]

**Суть:** 96 → 128 GiB RAM = +32 GiB бюджета. Можно поднять весь core до iq4_xs (4.25 bpw). Это изменит BPW с 3.4 до ~4.5 и PPL ожидаемо упадёт до ~8.0–8.5.

**Стоимость:** ~$100–200 за RAM.

## 4. Рекомендуемый порядок экспериментов

```
Эксперимент 1: Перераспределение бюджета (3.2 + 3.5)
  → attn_q = iq5_k, +5 слоёв down_exps = iq4_xs
  → Переквантизация ~1 час, замер PPL ~4.5 часа
  → Если PPL < 9.5 — успех

Эксперимент 2: Свой imatrix из Q8_0 (3.3)
  → Генерация imatrix (долго)
  → Переквантизация лучшим рецептом + новый imatrix
  → Замер PPL

Эксперимент 3: BF16 источник (3.1)
  → Скачать BF16 (~450 GiB)
  → Квантизация лучшим рецептом + imatrix
  → Замер PPL — это будет "gold standard" для данного BPW
```

## 5. Данные для будущих статей

### Факты, подтверждённые измерениями

1. **Скорость:** Tapered-RAM (91 GiB) в 6x быстрее UD-Q5 (151 GiB) на том же хосте (3.82 vs 0.62 t/s на tg32). Причина — swap pressure, не тип кванта.

2. **PPL:** При 3.4–3.5 bpw из Q8_0 источника PPL ≈ 9.7 на wikitext-2 (n_ctx=512). Это ~1 пункт хуже расчётных оценок.

3. **Attention vs experts:** Апгрейд attention с iq3_ks до q8_0 (+1.4 GiB) не снизил PPL. Dominant source of error — expert FFN, не attention.

4. **Imatrix mismatch:** Imatrix от BF16 применённый к Q8_0 квантизации не дал ожидаемого улучшения. Возможно несоответствие распределений.

5. **Размер > качество кванта:** Для swap-bound моделей "влезть в RAM" даёт 6x скорость, даже ценой более агрессивной квантизации.

### Гипотезы — проверенные

1. ~~Перераспределение бюджета от attention к экспертам снизит PPL~~ → **Частично подтверждено.** Deep-Taper v4 перераспределил бюджет и поднял expert BPW. PPL улучшился с 9.70 до 9.42, но разница скромная (0.28 пункта на +22 GiB).

2. ~~Attention fix (iq3_ks → q8_0) улучшит PPL~~ → **Опровергнуто.** v3.1 с attention q8_0 дал PPL 9.70, практически идентичный v2 с attention iq3_ks (9.53±0.66). Attention — 3% модели, его качество не влияет на PPL.

### Гипотезы — требующие проверки

1. BF16→iq3_ks даст PPL ~8.0–8.7 (устранение двойной квантизации — главный потенциальный выигрыш)
2. Imatrix, сгенерированный из Q8_0, даст лучший PPL чем imatrix от BF16
3. PPL ~9.4 — это пол для Q8_0 источника при любом BPW в диапазоне 3.4–4.3

## 7. Главные выводы для статей

### Вывод 1: Размер > BPW для скорости на ограниченной RAM

Tapered-RAM v3.1 (92 GiB, 3.46 bpw) в **6x быстрее** UD-Q5 (151 GiB, 5.0 bpw) на одном и том же хосте (95 GiB RAM). Причина — не тип кванта, а swap pressure. Модель, помещающаяся в RAM, радикально быстрее модели, не помещающейся.

### Вывод 2: Attention — не bottleneck PPL

Исправление attention с iq3_ks до q8_0 (+1.4 GiB) **не изменило** PPL (9.53 → 9.70). Attention — 3% весов модели. Expert FFN (95% весов) определяет PPL.

### Вывод 3: Перераспределение бюджета от attention к экспертам работает, но скромно

Deep-Taper v4 опустил attention (q8_0→iq5_k/q5_K) и поднял экспертов (core down: iq3_ks→iq4_xs). При +22 GiB и +0.8 BPW получил лишь 0.28 улучшения PPL. Закон убывающей отдачи.

### Вывод 4: Двойная квантизация — главный ограничитель

PPL ~9.4 при 4.26 bpw из Q8_0 vs расчётные ~8.5 при том же BPW из BF16 (оценки из рецептов). Разница ~1 пункт — это стоимость пути BF16→Q8_0→наш квант. Устранение промежуточного Q8_0 — самый перспективный путь улучшения.

### Вывод 5: Swap-bound ≠ непригодная

Deep-Taper v4 (114 GiB на 95 GiB RAM, ~19 GiB swap) показывает ~4 t/s в реальном использовании (после прогрева). Это сопоставимо с in-RAM версией (92 GiB, ~4 t/s). Для MoE-моделей умеренный swap не катастрофичен — demand-paged mmap + hot expert locking компенсируют.

### Вывод 6: Cold-start бенчмарки нерелевантны для swap-bound MoE

llama-bench без warmup показал 0.02 t/s для v4 — в 190x медленнее реальности (~4 t/s). Для swap-bound MoE warmup обязателен, cold-start числа не отражают пользовательский опыт.

## 8. Уточнение: IQ vs Q типы (2026-03-22)

### Ранняя ошибка в оценках

В ранних оценках мы сравнивали наш PPL 9.42 (iq-based, из Q8_0) с гипотетическим Q4_K_M PPL ~5–6.5 и делали вывод, что IQ-кванты хуже. **Это было некорректное сравнение:**

- Наш результат: Q8_0 → iq mixed (3.19–5.5 bpw) = PPL 9.42
- Гипотетический Q4_K_M: BF16 → Q4_K_M uniform (4.8 bpw) = PPL ~5–6.5

Три переменные отличаются одновременно: **источник**, **BPW**, **равномерность**. Нельзя делать вывод о типе кванта.

### Техническая разница IQ vs Q

**Q-кванты**: линейная блочная квантизация (scale × int + min). Простая, быстрая, не требует imatrix.

**IQ-кванты**: нелинейная квантизация через lookup-таблицы. Оптимизирует распределение уровней. При том же BPW **теоретически лучше** Q. Но требует imatrix для полного потенциала.

### Правильное сравнение

При равных условиях (один источник, один BPW):
- iq4_xs (4.25 bpw) ≥ q4_K (4.5 bpw) по качеству
- IQ лучше Q при том же BPW, не хуже

### Реальные причины нашего PPL 9.42

1. **Двойная квантизация** (Q8_0 источник) — основной фактор, +0.5–1.0 PPL
2. **"Слабое звено"** — 68 тензоров в iq3_ks (3.19 bpw) тянут PPL вниз
3. **Imatrix mismatch** — imatrix от BF16 применён к Q8_0 весам

Если бы Q4_K_M квантовали из того же Q8_0 — его PPL тоже был бы ~7–9, не 5–6.5.

### Следствие для стратегии

Менять IQ на Q типы **бессмысленно** — проблема не в типе. Правильные направления:
1. Убрать "слабое звено" (iq3_ks → iq4_xs, вариант D)
2. Устранить двойную квантизацию (FP8/BF16 источник)
3. Использовать imatrix, соответствующий источнику

### Гипотеза "слабого звена" (testable)

PPL определяется не средним BPW, а **минимальным** BPW в модели. 68 тензоров в iq3_ks (3.19 bpw) вносят непропорционально большую ошибку.

Тест: вариант D (uniform iq4_xs, ~114.5 GiB, ~4.30 bpw) vs v4 (taper 3.19–5.5 bpw, ~114 GiB, ~4.26 bpw). Если D лучше — гипотеза подтверждена.

Это фундаментальный вопрос для всех MoE-квантизаций: **лучше ровный средний BPW или зонный taper с низкими минимумами?**

### Внешние подтверждения

**Данные из llama.cpp PR #5747 (ikawrakow, Mistral-7B, из BF16):**

| Квант | BPW | ln(PPL/base) | PPL деградация |
|-------|-----|-------------|---------------|
| IQ3_S | 3.52 | 0.0306 | +3.1% |
| IQ4_XS | 4.32 | 0.0079 | +0.8% |
| Q4_K_S | 4.57 | 0.0081 | +0.8% |
| Q4_K_M | 4.83 | 0.0060 | +0.6% |

**Ключевые выводы из внешних данных:**

1. **IQ4_XS (4.32 bpw) ≈ Q4_K_S (4.57 bpw)** по PPL — подтверждает, что IQ >= Q при равном bpw.
2. **IQ3_S даёт +3.1% PPL** на 7B модели — на 228B MoE эффект может быть **значительно сильнее** из-за компаундирования через 62 слоя × 256 экспертов.
3. **Разница IQ4_XS vs Q4_K_M = 0.2%** на 7B из BF16 — наша разница PPL (~100% от baseline) объясняется не типом кванта, а двойной квантизацией и iq3_ks слабым звеном.

**Данные из PR #4773 (ikawrakow, IQ2_XXS, ctx=4096):**

| Модель | Размер (GiB) | PPL |
|--------|-------------|-----|
| LLaMA-v2-7B | 1.73 | 7.07 |
| LLaMA-v2-13B | 3.30 | 5.73 |
| LLaMA-v2-70B | 17.03 | 4.08 |

Показывает: при том же BPW (2.06) **бОльшие модели дают лучший PPL**. Это подтверждает, что для 228B MoE iq4_xs должен давать хороший PPL — если источник правильный (BF16, не Q8_0).

## 10. Variant A Results (2026-03-24)

### Result

- **PPL = 9.33 ± 0.23** (64 chunks)
- Size: 124 GiB, BPW: 4.75
- Changes vs v4: all iq3_ks → iq4_xs (taper preserved, weak link removed)

### Complete PPL History

| Version | BPW | Min bpw | Size | PPL | Δ vs prev |
|---------|-----|---------|------|-----|-----------|
| v3.1 | 3.46 | 3.19 | 92 GiB | 9.70 | — |
| v4 | 4.26 | 3.19 | 114 GiB | 9.42 | -0.28 |
| **Variant A** | **4.75** | **4.25** | **124 GiB** | **9.33** | **-0.09** |

### Key Conclusion: Q8_0 Source is the Ceiling

All recipe optimizations combined (v3.1 → v4 → Variant A):
- Spent: **+34 GiB** (+1.3 BPW)
- Gained: **-0.37 PPL** (9.70 → 9.33)
- ROI: **0.01 PPL per GiB** — diminishing returns

The PPL floor from Q8_0 source is ~9.3. No amount of zone taper, asymmetry, or budget redistribution can break through it. The bottleneck is double quantization (BF16 → Q8_0 → our quant), not the recipe.

### What Actually Mattered

1. **Speed** — fitting in RAM (92 GiB) gave 6x speed improvement over UD-Q5 (151 GiB). This is the real practical win, independent of PPL.

2. **Methodology** — we proved that:
   - Attention does not affect MoE PPL (3% of weights)
   - Budget redistribution works but gives marginal returns from Q8_0
   - Minimum bpw ("weak link") matters more than average, but not dramatically from Q8_0
   - Zone taper is valid but insufficient to overcome source quality

3. **Infrastructure** — eval suite (23 tests), expert stats export, dashboard presets, quantization scripts — all reusable for future experiments.

4. **Understanding** — only two paths forward give meaningful PPL improvement:
   - FP8/BF16 source (estimated PPL 8.9–9.2)
   - More RAM (allows higher BPW, estimated PPL 8.0–8.5)

### Recommendation

Stop optimizing recipes from Q8_0 source. Every experiment gives <0.1 PPL improvement at this point. Next meaningful step is FP8 source quantization.
