# Eval Suite V2 — Сложные тесты для сравнения квантов

Дата: 2026-03-23

Цель: тесты, которые:
1. Дискриминируют между квантами (более точный квант = заметно лучший результат)
2. Сложнее базовых тестов v1
3. Не вызывают проблему пустых ответов (избегаем pure-math формат, который триггерил пустой content)

Общий максимум: **100 баллов** (10 тестов × 10 баллов).

---

## Как проводить

1. Запустить модель через llama-server с `-c 4096`
2. Подать каждый промпт через API (temperature=0.3, max_tokens=1500)
3. Записать ответ полностью
4. Оценить по критериям
5. Сравнить баллы между v4 и Variant D

## Тест V2-1: Многоуровневая абстракция (10 баллов)

### Промпт

```
У компании есть 3 проекта: Alpha, Beta, Gamma.
- Alpha приносит $100K/мес, требует 5 разработчиков, растёт на 10% в месяц
- Beta приносит $80K/мес, требует 3 разработчика, растёт на 20% в месяц
- Gamma приносит $50K/мес, требует 2 разработчика, растёт на 5% в месяц

У компании 8 разработчиков. Через 6 месяцев нужно выбрать только 2 проекта из 3.

1. Рассчитай доход каждого проекта через 6 месяцев с учётом роста
2. Рассчитай ROI (доход на одного разработчика) для каждого через 6 месяцев
3. Какие 2 проекта оставить и почему?
4. Есть ли вариант перераспределить разработчиков для лучшего результата?
```

### Правильные ответы (для проверки)

- Alpha через 6 мес: $100K × 1.1^6 = $177.1K/мес
- Beta через 6 мес: $80K × 1.2^6 = $238.9K/мес
- Gamma через 6 мес: $50K × 1.05^6 = $67.0K/мес
- ROI Alpha: $177.1K / 5 = $35.4K/dev
- ROI Beta: $238.9K / 3 = $79.6K/dev
- ROI Gamma: $67.0K / 2 = $33.5K/dev

### Критерии

| Баллы | Критерий |
|-------|---------|
| 3 | Правильный расчёт доходов через 6 мес (±5%) |
| 3 | Правильный ROI для каждого проекта |
| 2 | Логичный вывод: оставить Beta + Alpha (или Beta + Gamma с обоснованием) |
| 2 | Анализ перераспределения разработчиков (масштабируемость, риски) |

## Тест V2-2: Каскадная отладка (10 баллов)

### Промпт

```
Этот Python-код должен парсить CSV лог и возвращать топ-5 самых медленных API endpoints. Но он выдаёт неправильные результаты. Найди все проблемы и исправь.

import csv
from collections import defaultdict

def analyze_api_logs(csv_path):
    stats = defaultdict(list)

    with open(csv_path) as f:
        reader = csv.DictReader(f)
        for row in reader:
            endpoint = row['path']
            duration = row['duration_ms']
            status = row['status']

            if status == 200:
                stats[endpoint].append(duration)

    result = {}
    for endpoint, durations in stats.items():
        result[endpoint] = {
            'avg_ms': sum(durations) / len(durations),
            'max_ms': max(durations),
            'count': len(durations),
            'p95_ms': sorted(durations)[int(len(durations) * 0.95)]
        }

    top_5 = sorted(result.items(), key=lambda x: x[1]['avg_ms'])[:5]
    return top_5

# Пример CSV:
# timestamp,path,duration_ms,status
# 2024-01-01T00:00:00,/api/users,45,200
# 2024-01-01T00:00:01,/api/orders,120,200
# 2024-01-01T00:00:02,/api/users,55,500
```

### Баги (для проверки)

1. `status == 200` — сравнение str с int, всегда False → ни одна строка не обработается
2. `duration` — строка, не число → sum/max/sorted не работают корректно ("9" > "120")
3. `sorted(durations)[int(...)]` — index может выйти за границы (len=1, idx=0.95→0, OK, но при пустом списке — ZeroDivisionError)
4. `[:5]` без `reverse=True` — берёт 5 самых быстрых, а не медленных
5. Нет обработки пустого файла / отсутствующих колонок

### Критерии

| Баллы | Критерий |
|-------|---------|
| 3 | Найден баг 1: str vs int сравнение |
| 2 | Найден баг 2: строки вместо чисел |
| 2 | Найден баг 4: сортировка в неправильном направлении |
| 1 | Найден баг 3 или 5 |
| 2 | Предложен исправленный рабочий код |

| 2 | Корректная обработка скобок и унарного минуса |
| 1 | Код читаем и структурирован |

## Отличия от V1

1. **Нет pure-math промптов** — V1 тесты 5, 11, 13 давали пустые ответы. V2 встраивает математику в бизнес-контекст.
2. **Больше кода** — 3 из 10 тестов требуют рабочего кода (парсер, LRU cache, debug).
3. **Длиннее рассуждения** — контрфактическая история, системный дизайн, этическая дилемма требуют 300+ слов связного текста.
4. **Мультиязычность** — тест V2-9 проверяет 3 языка включая японский.
5. **Практичнее** — бизнес-расчёт, системный дизайн, этика — реальные задачи, не головоломки.
