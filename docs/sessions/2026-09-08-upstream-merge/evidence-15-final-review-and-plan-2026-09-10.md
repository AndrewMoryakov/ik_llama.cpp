## Итог ревью

Перед следующим продвижением `dev` нужны исправления в пяти областях.

1. **Границы выполнения.** `safe_exec_python` в
   `eval/llm_eval_suite_v2/eval_common.py:232-258` запускает текст ответа
   модели через `exec`; AST-фильтр не является изоляцией. Dashboard принимает
   имя исполняемого файла в `/api/launch`
   (`dashboard/dashboard_server.py:1013-1039`), а Windows terminal mode пишет
   аргументы и environment в `.bat` (`:213-220`).
2. **RTR.** `llama_rtr_auto_ncmoe_cpu_override` в `src/llama.cpp:5435-5445`
   выбирает первые N слоёв, тогда как single-device loader в
   `src/llama-load-tensors.cpp:274-286` выбирает последние N MoE-слоёв. Также
   forced `-rtr 1` выключает mmap и тем самым отменяет `--defer-experts` без
   предупреждения.
3. **Сохранность и происхождение результатов.** Moe trace открывает обычный
   output с `std::ios::trunc` в `examples/main/moe-trace.cpp:257`. `ci/run.sh`
   не раскрывает glob при очистке и дописывает старые логи. V2 eval-скрипты
   дописывают разные прогоны в постоянный `results.jsonl`.
4. **Измерения.** FQC-03 допускает текст вокруг JSON. Step0 parser выбирает
   последнюю совпавшую строку и требует fixture для `runs/tokens`. SQL-сравнение
   llama-bench не сохраняет весь контекст RTR.
5. **Сборочные инструкции.** Raptor-скрипт не возвращает `%BUILD_EXIT%` после
   build. В документации есть устаревшие Raptor handoff, путь Vulkan smoke,
   неполный build-gate, прежний список разрешённых тестовых отказов и
   противоречивый статус Step0.

Дубликат: маркировка I/O-метрики была записана и в evidence-12, и в
evidence-13, но является одной задачей. Буквальные `\\n` в старых commit
messages не меняют файлов проекта и не оправдывают переписывание истории.

## План

### 1. Сделать build и CI результаты достоверными

1. В `build_raptor_lake.bat` после отчёта завершать ошибочный путь через
   `exit /b %BUILD_EXIT%` и успешный через `exit /b 0`.
2. В `ci/run.sh` раскрывать glob вне кавычек либо создавать новый каталог
   результата; для свежего прогона не использовать `tee -a`.
3. В `FORK_WORKFLOW.md` записать отдельные команды clean configure, build,
   `ctest --test-dir` и smoke. Обновить список допустимых отказов только после
   актуального прогона.

**Проверка завершения:** в `cmd.exe` неудачная configure и неудачная build
возвращают ненулевой код даже при старых `build/bin` файлах; два CI-прогона
в одном указанном output не смешивают логи; документированные команды работают
из чистого каталога.

### 2. Закрыть границы выполнения кода

1. В dashboard разрешить только точный список поддерживаемых имён бинарников.
   Проверять тип args, путь и environment до запуска. В terminal mode передавать
   аргументы без сериализации пользовательского ввода в язык `.bat`.
2. Определить локальную модель доступа dashboard: токен или проверяемый Origin.
3. Для Fast-QC не выполнять код модели в процессе оценщика. Сохранить смысл
   задач через изолированный runner с ограничениями файловой системы, сети,
   времени и ресурсов. До появления runner помечать code-задачи как не
   выполненные, а итог как неполный.

**Проверка завершения:** unit-тесты отвергают абсолютный путь, `..`,
неразрешённое имя и неверный тип args; обычный разрешённый запуск остаётся
работоспособным. Regression-тест Fast-QC доказывает, что ответ модели не может
получить доступ к host-объектам, а runner завершается по timeout.

### 3. Согласовать RTR policy и loader

1. Вынести расчёт CPU MoE placement в общий механизм для auto-policy и loader.
   Пока это невозможно, auto возвращает UNKNOWN в случае одного устройства с
   частичным `-ncmoe`, а не разрешает repack по приближению.
2. В общем пути загрузки явно отклонять или предупреждать о сочетании
   `--defer-experts` и forced RTR. Выбранный контракт должен одинаково работать
   для CLI и API.
3. Расширить `tests/test-rtr-params.cpp`; добавить fixture placement для
   плотных начальных слоёв, неполного `ncmoe` и prediction layers.

**Проверка завершения:** policy и loader выдают одинаковый список CPU MoE
слоёв на fixture. Целевой Linux/GPU-прогон с ограниченной памятью подтверждает
выбранное поведение без молчаливой отмены deferred experts.
