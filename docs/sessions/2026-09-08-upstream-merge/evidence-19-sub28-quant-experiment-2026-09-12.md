# 19 — Эксперимент: MiniMax под 28 ГБ, где физический пол

Дата: 2026-09-12
Машина: DESKTOP-HENS8K7, Ryzen 9 7950X, 95 ГБ RAM
Квантизатор: `D:\ik_llama-unsloth\build\bin\Release\llama-quantize.exe`
Перплексия: `D:\build-zen4\bin\llama-perplexity.exe`
Исходник: `D:\MiniMax-M2.5-VariantA.gguf` (123.6 ГиБ)
Результат: `D:\MiniMax-M2.5-Taper28.gguf` (48.07 ГиБ)

## Результат одной строкой

Цель «не более 28 ГБ» недостижима квантизацией: физический пол ~43 ГиБ. Осмысленный
минимум тейпером — 48 ГиБ, и это уже граница заметной деградации: перплексия
13.98 против 9.95 у 91-ГиБ TaperedRAM, то есть вдвое меньший размер стоит +4.0.

## 1. Почему 28 ГБ невозможно

Эксперты — 97% модели, ~224 млрд параметров. Чтобы уложить их в 28 ГБ, нужно
~1.0 bpw на вес, а самый компактный пригодный тип ik_llama — `IQ1_S` (1.56 bpw,
`IQ1_S_R4` 1.5). Проверено холостым прогоном: **все эксперты в `iq1_s`** дают
`quant size = 44091.85 MB = 43.1 ГиБ`. Это дно палитры. Тейпер (края точнее)
может только увеличить размер, не уменьшить. 28 ГБ достижимо лишь прунингом
(выбросить эксперты/слои), а не квантованием; по evidence-8 (энтропия выбора
экспертов 0.919, горячего подмножества нет) прунинг на ~65% этой модели её
сломает.

## 2. Рецепт Taper28 (по мотивам Tapered-RAM, сдвинут вниз)

```
Edge   [0-1, 60-61]     down=iq3_ks   gate/up=iq2_s
Bridge [2-5, 56-59]     down=iq2_s    gate/up=iq2_xs
Core   [6-55]           iq1_s (база)
Attention / output / embeddings:      iq4_xs
ffn_gate_inp:                         f32
База:                                 IQ1_S
```

`--custom-q "blk\.(0|1|60|61)\.ffn_down_exps=iq3_ks,blk\.(0|1|60|61)\.ffn_gate_exps=iq2_s,blk\.(0|1|60|61)\.ffn_up_exps=iq2_s,blk\.(2|3|4|5|56|57|58|59)\.ffn_down_exps=iq2_s,blk\.(2|3|4|5|56|57|58|59)\.ffn_gate_exps=iq2_xs,blk\.(2|3|4|5|56|57|58|59)\.ffn_up_exps=iq2_xs"`

Dry-run спроектировал 49218.85 MB; факт совпал до байта. Матрица важности та же
`imatrix_minimax_m25_bf16.dat`, исходник `VariantA` (уже квант — потери двойные).

## 3. Замер

```
quant size = 49218.85 MB = 48.07 ГиБ   (QUANT_EXIT=0)
перплексия = 13.9754 ± 0.11669  (полный wikitext-2, 552 чанка, n_ctx=512,
             --no-mmap, build-zen4)   (PPL_EXIT=0)
```

| Модель | Размер | Ядро | PPL |
|---|---|---|---|
| v3.1 (из Q8_0) | 92 ГиБ | iq4_xs/iq3 | 9.70 ± 0.08 |
| TaperedRAM | 91 ГиБ | iq3_ks | 9.95 ± 0.08 |
| **Taper28** | **48 ГиБ** | **iq1_s** | **13.98 ± 0.12** |

Половина размера стоит +4.0 перплексии (~40% относительно). Деградация заметная,
но не разнос: NLL осмысленный, интервал узкий. Перплексия шла ~2× быстрее, чем у
91-ГиБ (меньше байт на токен).

## 4. Границы

- Качество за пределами перплексии не проверено — связность ответов ловит только
  живой прогон (планируется в Unsloth). Перплексия при iq1_s-ядре может
  недооценивать деградацию на длинных рассуждениях.
- Исходник — `VariantA`, уже квант: потери тройные (VariantA→iq1_s поверх
  исходного FP8). От BF16 тот же рецепт был бы чуть лучше, но пол 43 ГиБ не
  сдвинулся бы — он определяется числом параметров, а не точностью исходника.

## 5. Вывод

Для этой модели размерный коридор такой: ~43 ГиБ — жёсткий пол; ~48 ГиБ — первый
осмысленный тейпер с ощутимой, но не катастрофической потерей (PPL +4); 91 ГиБ
(TaperedRAM) — рабочая точка под 96 ГБ RAM (PPL 9.95). Ниже 43 ГиБ — только
прунинг, вне квантизации.
