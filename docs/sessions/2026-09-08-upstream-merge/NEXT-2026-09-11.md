## Связка с Unsloth (инференс через ik_llama)

Unsloth на 7950X использует ik_llama как бэкенд инференса вместо стокового
llama.cpp — ради оптимизаций под CPU/Zen4. Настраивается полем **«Custom
llama.cpp folder» → `D:\ik_llama-unsloth`** (та же папка продублирована в
переменной `UNSLOTH_LLAMA_CPP_PATH`).

Каталог самодостаточный: `build\bin\Release\` содержит `llama-server.exe` и
`llama-quantize.exe` с их DLL (`ggml/llama/mtmd`), в корне — `convert_hf_to_gguf.py`
и `gguf-py`. Всё из одного билда `D:\build-zen4` (Zen4/VNNI), поэтому exe и DLL
ABI-согласованы; подкладывать один бинарник к чужим библиотекам нельзя.

**Что понадобилось.** Unsloth запускает `llama-server` флагами своего форка
(`--fit`, `--no-webui`, `--props`, `--spec-default`, список растёт с
обновлениями), которых в ik_llama нет, — сервер падал с `unknown argument`.
Правка `common/common.cpp`: в толерантном режиме неизвестный `--` флаг
пропускается с предупреждением (и его значением), а не роняет сервер. Режим
включается двумя путями (любой из них): переменная
`IK_LLAMA_IGNORE_UNKNOWN_ARGS=1` **или** файл-маркер `IK_IGNORE_UNKNOWN_ARGS`
рядом с бинарником. **Рабочий механизм здесь — маркер-файл** (лежит в
`D:\ik_llama-unsloth\build\bin\Release\`): он не зависит от наследования
окружения, поэтому перезапуск Unsloth не нужен — сервер находит его по
собственному пути при каждом старте. Env-переменная оставлена как запасной путь,
но одна она не сработала: дерево процессов Unsloth Studio стартовало раньше
`setx` и переменную не унаследовало. Гейт (env или маркер) — обычный CLI форка
остаётся строгим. Коммиты `56b9b72`, `ff28516`, `439d483`. Проверено с
выключенной env: сервер стартует полным набором флагов Unsloth
(`ignoring unknown argument: --spec-default`, затем `HTTP server listening`).

**Как пересобрать/обновить после изменения исходника.** Собрать оба таргета из
патченного дерева и переложить весь набор целиком:
```
cmake --build D:uild-zen4 --target llama-server llama-quantize -j 16   (Ninja + vcvars64)
copy build-zen4in\{llama-server.exe, llama-quantize.exe, *.dll} -> D:\ik_llama-unslothuildin\Release
```
Копировать exe вместе с DLL из того же билда — иначе ABI разъедется.

**Границы.** Проверял сервинг на Qwen2.5-1.5B; крупные модели на CPU поднимутся,
но медленно. Тренировочный путь Unsloth на этой машине не работает вовсе — его
пакет не импортируется без GPU-акселератора (torch тут CPU-only), это к ik_llama
отношения не имеет. Откат связки: очистить поле / убрать `UNSLOTH_LLAMA_CPP_PATH`
— Unsloth вернётся на стоковый `~\.unsloth\llama.cpp`.
