# 00 — ИНДЕКС: ускорение MoE-инференса MiniMax M2.7 (CPU-only, ik_llama.cpp)

Набор спеков по ускорению инференса форка. Все находки привязаны к коду по `file:line`; недоказуемое помечено `[UNVERIFIED]`.

## Контекст задачи
- Модель **~110 GB** > RAM **96 GB** → **резидентность недостижима**, эксперты пейджатся с SSD (Samsung 970, Gen3, ~3.5 GB/s).
- Наблюдаемая скорость: **~1.5–2 t/s**. Гипотеза: **disk-bound** (~4.9 GB/токен ÷ 3.5 GB/s ≈ 1.4 t/s).
- Кванты на пределе, RAM разогнана максимально → ищем выигрыш в **софте/модели**.

## ⚠️ Главный гейт перед любой реализацией
**Сначала `analysis-3` (ШАГ 0).** Оценка «disk-bound» — worst-case. Измерь реальные GB/токен с диска:
- если ≈ 4.9 GB → disk-bound подтверждён → приоритет: префетч / обрезка bytes/token;
- если ≪ 4.9 GB → часть весов в page cache → возможно RAM-bound → **приоритеты переворачиваются**.

## Три подтверждённых факта (grounded в дереве форка)
1. **`-ser` неактивен в HEAD** — `ggml_top_k_thresh` только объявление + определение + один закомментированный вызов (`src/llama-build-context.cpp:1089`); живой путь `ggml_top_k`. Активация = раскомментировать + пересобрать.
2. **Per-expert tiered-quant невыразим** — эксперты слоя = один слитый 3D-тензор, единый тип; `--custom-q` даёт только per-layer гранулярность (`analysis-2` §2).
3. **`n_expert_used` переопределяется на рантайме** — цепочка `--override-kv` → `expert_used_count` → `hparams` → `ggml_top_k` подтверждена (`src/llama-arch.cpp:120`, `llama-hparams.cpp:73`, `llama-build-context.cpp:1091`).

## Рекомендованный порядок действий (по возрастанию затрат/риска)
1. **ШАГ 0** (`analysis-3`) — подтвердить bottleneck.
2. **Эксперимент №1** (`analysis-5`) — `--override-kv ...expert_used_count=int:6` (top-8→6→4), замер t/s + perplexity. Нулевой риск, 10 минут.
3. **Prompt-lookup** (`analysis-5` №4) — бесплатно, без второй модели.
4. **Спекулятивный драфт** (`analysis-5` №3) — если есть совместимый драфт.
5. **Батч-префетч + VirtualLock горячих** (`analysis-1`, `analysis-5` №5–6) — инженерная работа, высокий потолок.
6. **Прунинг 256→~176 экспертов** (`analysis-2` §3) — оффлайн, максимальный выигрыш, единственный путь к полной резидентности (~80 GB → ~8–10 t/s).

## Правило валидации (для КАЖДОГО изменения)
`llama-perplexity` на **domain-holdout** (не wikitext): +2% accept / +5% reject. Для прунинга дополнительно — routing-coverage обрезанных экспертов <0.1% на holdout.

## Что достижимо на целевом железе (ПРОЕКЦИЯ, не замеры)

⚠️ **Это оценки, а не измерения.** Baseline ещё не снят (нет доступа к целевой
машине). Числа — диапазоны, подлежат замене/подтверждению после реального ШАГ 0
(`analysis-3` / `step0/step0-bench.ps1`).

Целевое железо: Ryzen 9 7950X, 96 ГБ DDR5, MiniMax-M2.7 ~110 ГБ, ~4.9 ГБ/токен
активных весов, CPU-only.

**Жёсткий потолок:** полоса DDR5 dual-channel (~65 ГБ/с с EXPO) ÷ 4.9 ГБ/токен
≈ 75 мс → теоретически ~13 t/s, реально **~7–10 t/s** (если модель целиком в RAM).
Выше него — только снижая байт/токен (меньше экспертов, агрессивнее квант) или
спекуляцией. AVX-512 не бутылочное горлышко (память, не счёт); AMX — Intel-only.

| Тир | Вмешательство | Ожидаемо | Уверенность | Детали |
|---|---|---|---|---|
| 0 | сейчас, ничего | **1.5–2 t/s** (disk-bound) | факт | — |
| 1 | top-k override (8→6/4) + пиннинг горячих экспертов (`-ot`/mlock) + large pages + EXPO | **~3–5 t/s** | средняя | `analysis-5` №1, `analysis-2`, план E |
| 2 | +Gen5 NVMe (~3→~12 ГБ/с) | **~4–6 t/s** | средняя | план A |
| 3 | асинхронный prefetch экспертов (правка форка) | **~5–7 t/s** | ниже средней* | `analysis-1` |
| 4 | прунинг ~30% мёртвых экспертов (256→~176) → модель ~80 ГБ влезает в RAM | **~7–10 t/s** | высокая по скорости** | `analysis-2` §3 |

\* Тир 3 зависит от точности cross-layer предсказания экспертов — `[UNVERIFIED]`.
\*\* По скорости уверенность высокая (это чистая полоса RAM); по **качеству** —
обязательна валидация (см. «Правило валидации» выше).

**Выводы:**
- Цель **5 t/s достижима** — дешёвый путь Тир 1 (+возможно Тир 2).
- **~7–10 t/s — реалистичный стретч**, надёжный путь — **Тир 4 (прунинг, чтобы
  модель влезла в RAM)**: превращает disk-bound в RAM-bound, убирает диск из
  steady-state. Gen5 SSD — страховка, если прунинг режет качество сильнее допустимого.
- **>10 t/s** — только осознанным разменом качества (`-ser`/top-k=4) или
  амортизацией (prompt-lookup на повторяющихся задачах).
- Общий риск-гейт: всё крупное (прунинг, top-k↓) разменивает качество → каждый
  шаг через `llama-perplexity` на domain-holdout.
