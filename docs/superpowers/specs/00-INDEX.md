# 00 — ИНДЕКС: ускорение MoE-инференса MiniMax M2.7 (CPU-only, ik_llama.cpp)

Набор спеков по ускорению инференса форка. Все находки привязаны к коду по `file:line`; недоказуемое помечено `[UNVERIFIED]`.

## Контекст задачи
- Модель **~110 GB** > RAM **96 GB** → **резидентность недостижима**, эксперты пейджатся с SSD (Samsung 970, Gen3, ~3.5 GB/s).
- Наблюдаемая скорость: **~1.5–2 t/s**. Гипотеза: **disk-bound** (~4.9 GB/токен ÷ 3.5 GB/s ≈ 1.4 t/s).
- Кванты на пределе, RAM разогнана максимально → ищем выигрыш в **софте/модели**.

## ⚠️ Главный гейт перед любой реализацией
**Сначала `analysis-3` (ШАГ 0).** Оценка «disk-bound» — worst-case. Измерь реальные GB/токен с диска:
- если ≈ 4.9 GB → disk-bound подтверждён → приоритет: префетч / обрезка bytes/token;
- если ≪ 4.9 GB → часть весов в page cache → возможно RAM-bound → **приоритеты переворачиваются**.

## Три подтверждённых факта (grounded в дереве форка)
1. **`-ser` неактивен в HEAD** — `ggml_top_k_thresh` только объявление + определение + один закомментированный вызов (`src/llama-build-context.cpp:1089`); живой путь `ggml_top_k`. Активация = раскомментировать + пересобрать.
2. **Per-expert tiered-quant невыразим** — эксперты слоя = один слитый 3D-тензор, единый тип; `--custom-q` даёт только per-layer гранулярность (`analysis-2` §2).
3. **`n_expert_used` переопределяется на рантайме** — цепочка `--override-kv` → `expert_used_count` → `hparams` → `ggml_top_k` подтверждена (`src/llama-arch.cpp:120`, `llama-hparams.cpp:73`, `llama-build-context.cpp:1091`).

## Рекомендованный порядок действий (по возрастанию затрат/риска)
1. **ШАГ 0** (`analysis-3`) — подтвердить bottleneck.
2. **Эксперимент №1** (`analysis-5`) — `--override-kv ...expert_used_count=int:6` (top-8→6→4), замер t/s + perplexity. Нулевой риск, 10 минут.
3. **Prompt-lookup** (`analysis-5` №4) — бесплатно, без второй модели.
4. **Спекулятивный драфт** (`analysis-5` №3) — если есть совместимый драфт.
5. **Батч-префетч + VirtualLock горячих** (`analysis-1`, `analysis-5` №5–6) — инженерная работа, высокий потолок.
6. **Прунинг 256→~176 экспертов** (`analysis-2` §3) — оффлайн, максимальный выигрыш, единственный путь к полной резидентности (~80 GB → ~8–10 t/s).
