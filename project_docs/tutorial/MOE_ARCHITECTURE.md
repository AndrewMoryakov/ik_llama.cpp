# Архитектура MoE: как устроена модель изнутри

Этот документ объясняет внутреннее устройство MoE-модели. Он отвечает на вопросы "что такое эксперт", "как устроены блоки", "как модель обучается" и "почему квантизация работает именно так".

Если вы уже прочитали `MINI_TUTORIAL.md`, вы знаете, как модель ведёт себя во время inference. Этот документ объясняет, **почему** она так устроена.

---

## 1. Путь токена через модель

Токен проходит через модель **последовательно**, один блок за другим:

```
Токен → Embedding → Блок 0 → Блок 1 → ... → Блок 61 → Output head → Вероятности
```

- **Embedding** (`token_embd`) — таблица, которая превращает номер токена в вектор чисел. Один тензор на всю модель.
- **Блоки** (62 штуки у MiniMax M2.5) — основная обработка. Каждый блок преобразует вектор, постепенно "переваривая" смысл.
- **Output head** (`output`) — обратная проекция: превращает финальный вектор в вероятности следующего токена.

Пропустить блок нельзя. Порядок фиксирован.

---

## 2. Что внутри каждого блока

Каждый из 62 блоков содержит две основные части:

### Attention

Механизм внимания — токен "смотрит" на все предыдущие токены в контексте и решает, на что обратить внимание. Состоит из:

- `attn_q` — запрос ("что я ищу?")
- `attn_k` — ключ ("что я содержу?")
- `attn_v` — значение ("что я могу дать?")
- `attn_output` — выходная проекция
- `attn_q_norm`, `attn_k_norm` — нормализация (у MiniMax M2.5 отдельные нормы для Q и K)

Attention одинаков в каждом блоке по структуре, но веса разные — каждый блок научился "обращать внимание" на разные аспекты.

### Expert FFN (Mixture of Experts)

Это то, что делает MoE особенной. Вместо одного FFN (Feed-Forward Network), как в dense-модели, здесь **256 отдельных маленьких FFN** — "экспертов".

Каждый эксперт — это три матрицы:
- `ffn_gate_exps` — фильтр ("что пропустить")
- `ffn_up_exps` — расширение
- `ffn_down_exps` — сжатие обратно

Плюс:
- `ffn_gate_inp` — **роутер**, который решает какие 8 из 256 экспертов активировать
- `ffn_norm` — нормализация перед FFN
- `exp_probs_b` — bias вероятностей экспертов

### Что происходит при обработке токена в одном блоке

1. **Attention**: токен взаимодействует с контекстом
2. **Роутер**: смотрит на результат и выбирает 8 из 256 экспертов
3. **8 выбранных экспертов**: каждый обрабатывает вектор, результаты взвешенно смешиваются
4. Результат передаётся в следующий блок

---

## 3. Что такое "эксперт"

Эксперт — это просто **небольшая нейронная сеть** (три матрицы весов), которая преобразует вектор. Ничего магического.

Слово "эксперт" — метафора. Никто не программировал "эксперта по коду" или "эксперта по биологии". Это просто набор чисел, который при обучении оказался полезным для определённых паттернов.

### Чем эксперт отличается от блока (слоя)

- **Блок** — это этап обработки. Все блоки проходятся последовательно. Пропустить нельзя.
- **Эксперт** — это один из вариантов обработки **внутри** блока. Роутер выбирает 8 из 256. Остальные 248 не участвуют.

### Специализация экспертов

Исследования показывают, что специализация **есть, но нечёткая**:

- Эксперты не делятся строго на "эксперт по коду" и "эксперт по биологии"
- Скорее каждый эксперт реагирует на определённые **статистические паттерны** во внутреннем представлении токена
- Один эксперт может активироваться и на коде, и на математике, и на структурированных списках — потому что у них похожая внутренняя структура
- В одном блоке может быть несколько экспертов, хорошо работающих с кодом, но каждый реагирует на разные аспекты

### Масштаб

MiniMax M2.5:
- 62 блока × 256 экспертов = **15 872** экспертов всего
- На один токен активируется 62 × 8 = **496** экспертов (~3%)
- Каждый эксперт — три тензора, каждый ~1.2 GiB в Q8_0

Expert FFN — это ~95% веса модели. Именно на них делается основная экономия при квантизации.

---

## 4. Роутер

У каждого блока **свой роутер** — маленький тензор `ffn_gate_inp` (3072×256, ~3 МБ).

Роутер блока N видит только экспертов блока N. Никакой координации между роутерами разных блоков нет — каждый принимает решение независимо.

Роутер — это обучаемый слой. Он не запрограммирован вручную, а научился направлять токены к нужным экспертам в процессе обучения.

---

## 5. Специализация блоков

Блоки тоже специализируются, но иначе, чем эксперты. Они образуют **иерархию абстракции**:

- **Ранние блоки** (0–4) — базовые паттерны: синтаксис, морфология, поверхностная структура
- **Средние блоки** (5–56) — семантика, связи, промежуточные рассуждения
- **Поздние блоки** (57–61) — высокоуровневые рассуждения, финальное формирование ответа

Это возникает естественно из-за последовательной архитектуры: блок 0 видит только "сырой" вход, а блок 61 видит уже многократно переработанное представление.

Именно поэтому при квантизации ранние и поздние блоки (edge) квантуют точнее — ошибки на входе и выходе модели влияют на качество сильнее.

## 6. Как обучается модель

### Общий процесс

Вся модель (все 62 блока, все роутеры, все 15 872 эксперта) обучается **одновременно** на одной задаче — предсказание следующего токена.

1. Модели показывают текст
2. Она предсказывает следующий токен
3. Ошибка предсказания — **loss** (потеря)
4. Вычисляется **градиент** — направление, в котором нужно изменить веса, чтобы уменьшить ошибку
5. Веса сдвигаются в этом направлении
6. Повторить миллионы раз

### Что такое градиент

Градиент — это математический ответ на вопрос: "в какую сторону и насколько нужно подвинуть каждое число в сети, чтобы ошибка уменьшилась?"

Технически это производная функции потерь по каждому параметру. Градиенты текут через всю цепочку от выхода к входу (backpropagation — обратное распространение ошибки).

### Как возникает специализация экспертов

Никто вручную не назначает "блок 5 — грамматика, блок 40 — логика". При инициализации все 256 экспертов в каждом блоке — случайные числа, практически одинаковые.

Потом происходит **дивергенция**:
1. Один эксперт случайно оказывается чуть лучше на токенах про код
2. Роутер начинает чаще посылать код к нему
3. Эксперт получает больше "кодовых" градиентов и ещё больше специализируется
4. Петля обратной связи закрепляет специализацию

### Load balancing loss

Единственное ручное вмешательство в процесс специализации.

Без коррекции роутер может "залипнуть" — направлять все токены в 5–10 экспертов, а остальные 250 оставить без обучения (dead experts). Поэтому к функции потерь добавляют **штраф за неравномерную нагрузку** — чтобы все эксперты получали примерно одинаковое количество токенов.

Это единственное, что задаёт человек. Всё остальное модель выучивает сама.

### Почему 256 экспертов, а не 16 или 10 000

Компромисс:
- **Мало** экспертов → меньше специализация, меньше "знаний" в модели
- **Много** экспертов → сложнее обучить, больше dead experts, больше памяти
- **256** при выборе 8 — эмпирически хороший баланс для модели такого масштаба

---

## 7. Почему MoE хорошо отзывается на квантизацию

Раз на каждый токен читаются только 496 из 15 872 экспертов, основное узкое место — **пропускная способность памяти**, а не вычисления.

Агрессивная квантизация (например, iq3_ks) уменьшает размер экспертов → меньше данных читать из RAM → быстрее inference. При этом качество каждого отдельного эксперта снижается незначительно, потому что эксперты маленькие и их много.

Именно поэтому MoE-модели можно квантовать агрессивнее, чем dense-модели того же "размера по параметрам", без катастрофической потери качества.

## 8. Почему разные тензоры квантуют по-разному

### `down_exps` важнее `gate_up_exps`

`down_exps` — это выходная проекция эксперта. Она непосредственно формирует результат, который передаётся дальше. Ошибки в `down_exps` напрямую искажают выход.

`gate_exps` и `up_exps` — входная часть. Они фильтруют и расширяют вектор. Ошибки здесь частично компенсируются последующим `down_exps`.

Поэтому при ограниченном бюджете байтов рациональнее вкладываться в точность `down_exps`.

### Edge-слои точнее, чем core

- **Ранние слои** формируют базовые представления. Ошибка на входе **накапливается** через все последующие 60 блоков.
- **Поздние слои** финализируют выход. Ошибка здесь **напрямую** влияет на предсказание.
- **Средние слои** — ошибки частично компенсируются соседними блоками и усредняются по массе.

### Attention всегда в высоком качестве

Attention — shared path, работает на каждом токене. Он маленький относительно экспертов (~2.73 GiB vs ~86 GiB expert FFN), но критичен для качества. Экономия на нём даёт мало байтов, но заметно роняет качество.

---

## 9. Компоненты вне блоков

| Компонент | Тензор | Размер | Роль |
|-----------|--------|--------|------|
| Embeddings | `token_embd` | ~0.6 GiB (Q8_0) | Вход: токен → вектор |
| Output head | `output` | ~0.6 GiB (Q8_0) | Выход: вектор → вероятности токенов |
| Output norm | `output_norm` | ~0.012 МБ | Нормализация перед выходом |

Embeddings и Output head — "дешёвые" для улучшения. Подъём их до Q8_0 стоит десятки мегабайт, но заметно влияет на качество входа и выхода.

## 10. Тензорная карта MiniMax M2.5

Полный набор тензоров для одного блока `blk.N`:

```
blk.N.attn_norm          нормализация перед attention       f32     0.012 МБ
blk.N.attn_q             query projection                   q8_0    19 МБ
blk.N.attn_k             key projection                     q8_0    3.2 МБ
blk.N.attn_v             value projection                   q8_0    3.2 МБ
blk.N.attn_output        output projection                  q8_0    19 МБ
blk.N.attn_q_norm        query normalization                f32     0.023 МБ
blk.N.attn_k_norm        key normalization                  f32     0.004 МБ
blk.N.ffn_norm           нормализация перед FFN             f32     0.012 МБ
blk.N.ffn_gate_inp       роутер (256 экспертов)             f32     3 МБ
blk.N.ffn_gate_exps      gate-тензоры экспертов [256]       q8_0    1224 МБ
blk.N.ffn_up_exps        up-тензоры экспертов [256]         q8_0    1224 МБ
blk.N.ffn_down_exps      down-тензоры экспертов [256]       q8_0    1224 МБ
blk.N.exp_probs_b        bias вероятностей экспертов        f32     0.001 МБ
```

Итого на блок: ~3.7 GiB (в Q8_0), из которых ~3.6 GiB — expert FFN.
