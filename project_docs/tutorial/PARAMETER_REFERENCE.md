# Parameter Reference

Это справочник по параметрам дашборда.

Формат каждого пункта:
- что это
- когда трогать
- когда не трогать
- что произойдет при неудачной настройке

## 1. Basics

### Model path

Что это:
- путь к `GGUF` модели

Зачем нужно:
- дашборд использует путь, чтобы определить размер модели, семейство, split-части и построить команду

Если указать неверно:
- автоконфигурация потеряет смысл
- family detection и size detection будут ошибочны

### Model size (GB)

Что это:
- суммарный размер файлов модели

Зачем нужно:
- от этого зависит главный вопрос: `in-RAM` или `swap-bound`

Когда менять вручную:
- только если автодетект не сработал

Что будет при ошибке:
- дашборд может предложить не тот runtime profile
- например, посчитать huge модель "in-RAM" и дать слишком агрессивный layout-first профиль

### Model type

Что это:
- `Dense` или `MoE`

Когда менять вручную:
- если GGUF metadata не позволяет уверенно определить тип

Что будет при ошибке:
- рекомендации по `rtr`, `muge`, `SER`, hot experts и threads будут неверными

### GPU layers (`-ngl`)

Что это:
- сколько слоев попытаться вынести на GPU

Для этого форка и текущего хоста:
- CPU-only baseline обычно означает `0`

Что будет при ошибке:
- на системе без подходящей GPU это либо не даст эффекта, либо создаст ложное ощущение, что модель настроена корректно, хотя реальный target-путь другой

## 2. Performance

### Workload

Варианты:
- `Mixed (PG)`
- `TG-only`
- `Prompt / PP`

Что это:
- какой путь исполнения вы оптимизируете

Когда менять:
- всегда осознанно

Что будет при ошибке:
- вы получите рекомендации для другого сценария
- самый частый провал: настроить `TG-only`, а потом удивляться, что в реальном чате `PG` ведет себя иначе

### Threads (`-t`)

Что это:
- число потоков вычислений

Validated baseline на Zen4 dual-CCD:
- `16`

Когда менять:
- если модель in-RAM и вы хотите A/B проверить `24/32`
- если у вас другое железо

Что будет при неудачном значении:
- слишком мало: недогрузите CPU
- слишком много: получите contention и падение эффективности, особенно на MoE

### Threads batch (`-tb`)

Что это:
- отдельные потоки для prompt processing

Когда менять:
- если вы уже увидели, что `PP` и `TG` масштабируются по-разному

Когда не менять:
- если вы еще не проверили базовый профиль

Что будет при ошибке:
- можно замедлить prompt без явной пользы

### Context size (`-c`)

Что это:
- размер контекстного окна

Когда менять:
- если вам реально нужен больший контекст

Что будет при слишком большом значении:
- вырастет KV cache
- вырастет RAM pressure
- huge-model scenario станет тяжелее

### Batch size (`-b`)

Что это:
- логический batch для prompt processing

Когда менять:
- если вы настраиваете длинные prompt'ы и понимаете компромисс память/скорость

Что будет при ошибке:
- слишком большой batch может упереться в память
- слишком маленький замедлит PP без причины

### Micro-batch (`-ub`)

Что это:
- физический внутренний batch

Когда менять:
- только если понимаете внутренний компромисс между peak memory и скоростью PP

Что будет при ошибке:
- бессмысленная потеря производительности или памяти

## 3. Optimization

### Flash Attention (`-fa`)

Статус:
- validated baseline

Что это:
- оптимизированный path для attention

Когда держать включенным:
- почти всегда на текущем Zen4 baseline

Когда выключать:
- только для диагностики, compatibility checks или осознанного A/B

Что будет при ошибке:
- mixed path и prompt-side attention могут стать медленнее

### Runtime Repack (`-rtr`)

Статус:
- validated, но family-dependent

Режимы:
- `off`
- `on`
- `auto`

Практическая логика:
- `Qwen3MoE`, `gpt-oss`: старт обычно с `auto`
- `MiniMax`: safest baseline сейчас `off`

Что будет при ошибке:
- in-RAM модель может недополучить throughput
- huge swap-bound модель может получить лишний working set, плохой startup и деградацию wall-clock

### Merge Up+Gate (`-muge`)

Статус:
- не validated как стабильный win

Когда трогать:
- только для адресного A/B

Когда не трогать:
- huge swap-bound MoE
- baseline launch

Что будет при ошибке:
- рост memory pressure без полезного выигрыша

### KV Cache K / V (`-ctk`, `-ctv`)

Статус:
- validated baseline: `q8_0`

Что это:
- квантизация KV cache

Когда трогать:
- если не помещается нужный контекст
- если вы целенаправленно освобождаете память под huge-model workload

Что будет при ошибке:
- слишком тяжелый тип съест лишнюю память
- слишком агрессивный без проверки может повлиять на качество или устойчивость на длинном контексте

### MLA (`-mla`)

Что это:
- режим MLA для архитектур, которые его поддерживают

Без явной причины:
- оставлять `auto`

Что будет при ошибке:
- можно выбрать path, который не оптимален для модели или вообще не нужен

### Smart Expert Reduction (`-ser`)

Статус:
- experimental

Что это:
- router-side pruning для слабых экспертов

Когда трогать:
- только в осознанном A/B на huge MoE

Что будет при ошибке:
- возможна деградация качества
- можно получить красивую идею без реальной пользы в throughput

### Hot Expert Budget (`IK_LLAMA_HOT_EXPERT_BUDGET`)

Статус:
- experimental, MiniMax-oriented

Что это:
- размер hot-набора экспертов после prompt

Когда трогать:
- только на huge swap-bound MoE, прежде всего `MiniMax`

Когда не трогать:
- `Qwen3MoE`
- `gpt-oss`
- любые семейства, где эффект не проверен

Что будет при ошибке:
- слишком маленький budget не поможет
- слишком большой budget увеличит RAM pressure без гарантии выигрыша

Что важно по текущему состоянию:
- короткий quick check когда-то подсветил большие бюджеты как возможный кандидат
- но первый более длинный controlled `MiniMax` run не оправдал повышение default выше legacy `16`
- поэтому safest user-facing answer сейчас: оставить `0`, то есть не переопределять runtime default

### Graph Reuse (`-gr`)

Статус:
- default ON

Когда менять:
- почти никогда

Что будет при ошибке:
- лишняя работа на построение графа

### Merge QKV (`-mqkv`)

Статус:
- experimental

Когда трогать:
- только для targeted checks

Что будет при ошибке:
- сложность и потенциальная регрессия без подтвержденного общего выигрыша

### K-Cache Hadamard (`-khad`)

Когда трогать:
- только если вы уже используете quantized K-cache и понимаете зачем это нужно

Что будет при ошибке:
- вы просто добавите лишнюю сложность без практической пользы

### Fused MoE / Fused Up*Gate (`-no-fmoe`, `-no-fug`)

Статус:
- базово оставлять включенными

Когда трогать:
- только для debug/diagnostics

Что будет при ошибке:
- лишняя деградация compute path

## 4. Server

### Host / Port

Что это:
- где будет слушать `llama-server`

Риск неверной настройки:
- вы не сможете подключиться к API
- или случайно откроете его слишком широко

### Parallel sequences (`-np`)

Что это:
- число одновременных слотов

Что будет при ошибке:
- слишком большое значение съест память на KV cache
- для huge моделей может резко ухудшить общий runtime

### API key

Что это:
- базовая защита HTTP API

### HTTP threads

Что это:
- потоки обслуживания HTTP, а не основной inference path

Что будет при ошибке:
- можно избыточно усложнить серверный режим без пользы для inference

## 5. Advanced

### Seed (`-s`)

Что это:
- seed генератора случайных чисел

Обычно:
- `-1`

### Predict tokens (`-n`)

Что это:
- сколько токенов максимум генерировать

Риск ошибки:
- пользователь думает, что модель "сломалась", хотя просто уперся в ограничение

### mmap

Что это:
- memory-mapped I/O

Почему важно:
- для huge swap-bound моделей это один из базовых механизмов выживания

Что важно помнить:
- `rtr=on` форсирует путь без normal mmap behavior
- `rtr=auto` нельзя трактовать как постоянное `no mmap`; решение остается за runtime policy

### mlock

Что это:
- попытка удержать модель в RAM

Когда полезно:
- в отдельных управляемых сценариях

Когда опасно:
- huge модель больше RAM все равно не "влезет" magically
- можно усилить давление на систему

### NUMA

Для текущего single-socket desktop baseline:
- обычно не трогать

### Defrag threshold (`-dt`)

Что это:
- дефрагментация KV cache

Когда трогать:
- только если у вас длинные живущие сессии и вы понимаете проблему fragmentation

## 6. Meta-controls

### Auto-configure

Что это:
- knowledge-layer, а не истина последней инстанции

Правильное использование:
- как хороший старт
- не как замену мышлению

### Generated Command

Что это:
- лучший способ увидеть, во что реально превратился ваш UI-профиль

Полезное правило:
- если вы не готовы запустить эту команду вручную, значит конфигурация еще не понята до конца

### Export / Import JSON

Зачем нужно:
- фиксировать рабочие профили
- сравнивать профили между моделями и экспериментами
