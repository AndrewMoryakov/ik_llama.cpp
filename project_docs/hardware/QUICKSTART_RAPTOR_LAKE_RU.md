# Краткое руководство — i7-1360p / 16 GB ноутбук

Протестированная конфигурация: Intel Core i7-1360p (4P+8E ядер, AVX-VNNI, без AVX-512),
16 ГБ DDR5, NVMe SSD, только CPU (без дискретной видеокарты).
Ветка сборки: `feature/raptor-lake-laptop`.

---

## 1. Сборка

```
build_raptor_lake.bat
```

Требуется Visual Studio 2022 Community по умолчательному пути установки.
Время сборки: ~5–8 минут (используется Ninja, реальный `-j 8`).

Готовые бинарники в `build\bin\`:
`llama-cli.exe`, `llama-server.exe`, `llama-bench.exe`, `llama-quantize.exe`

---

## 2. Запуск модели

```
build\bin\llama-cli.exe -m <модель.gguf> -t 4 -fa 1 -rtr auto [ваши флаги]
```

**Три флага, которые всегда нужно выставлять:**

| Флаг | Значение | Почему |
|---|---|---|
| `-t` | `4` | Только P-ядра. Все бо́льшие значения (8, 12, 16) медленнее из-за накладных расходов синхронизации OpenMP. |
| `-fa` | `1` | Flash attention. Всегда быстрее, никаких недостатков. |
| `-rtr` | `auto` | Политика сама решает: KEEP для небольших моделей (в памяти, AVX-VNNI активен), DISABLE для больших MoE (потоковое чтение с диска). |

> **Не использовать `-ctk q8_0`** — квантизация KV-кеша не поддерживается
> в CPU-only сборках и вызывает ошибку "failed to create context".

---

## 3. Что помещается в RAM

Политика `-rtr auto` использует **90% от общего объёма RAM (~14,1 ГБ)** как
порог для MoE-моделей. Для dense-моделей используется проверка доступной памяти.

| Класс модели | Типичный размер | Решение `-rtr auto` | Примечания |
|---|---|---|---|
| 7B Q4_K_M | ~4 ГБ | **KEEP** (в RAM) | Комфортно |
| 9B Q4_K_M | ~5,7 ГБ | **KEEP** | Замерено на GLM-Z1-9B |
| 14B dense Q4_K_M | ~8,4 ГБ | **KEEP** | Замерено на phi-4 |
| MoE ≤ 14 ГБ | разный | **KEEP** | Пограничный случай; смотреть лог |
| MoE > 14 ГБ | 17–25 ГБ | **DISABLE** (mmap) | Работает с диска |

При KEEP активный AVX-VNNI repacking даёт **+52% к скорости генерации (TG)**
по сравнению со сборкой без repacking.

При срабатывании DISABLE в логе появляется:
```
--run-time-repack auto: disabled (MoE model X GiB > 90% of RAM 15.7 GiB)
```
Модель загружается и работает через mmap — просто медленнее (ограничена диском).

## 4. Измеренная производительность

Все числа: `-t 4 -fa 1 -rtr 2` (или `rtr=auto` KEEP), сборка `bfff3fb7`.

| Модель | Размер | PP tok/s | TG tok/s | Примечания |
|---|---|---|---|---|
| GLM-Z1-9B Q4_K_M | 5,73 ГБ | 20,78 | 4,63 | Базовый показатель в RAM |
| phi-4 Q4_K_M (14B) | 8,43 ГБ | 10,36 | 1,59 | Dense 14B; ограничен температурным throttle |
| Qwen3-Coder-30B Q4_K_M | 17,35 ГБ | — | ~1,7 | С диска (NVMe холодный) |
| Qwen3-42B MXFP4_MOE | 22,0 ГБ | — | ~2,6 | С диска (файл в кеше ОС) |
| ERNIE-4.5-21B Q8_K_XL | 24,8 ГБ | — | ~1,2 | С диска |

PP на длинном промпте (512 токенов) для disk-bound MoE вызывает аварийное
завершение (MoE prefetch пытается обратиться к памяти сверх доступной).
С такими моделями используйте короткие промпты.

---

## 5. Температурное поведение

i7-1360p резко сбрасывает частоты при длительной нагрузке инференса.

- При интерактивном использовании: проблем нет — между ответами чип успевает остыть.
- При бенчмаркинге: используйте `-r 1` с паузой 30 с между моделями.
  С `-r 3` тяжёлая модель (14B+) в среднем выдаёт числа в 2–3 раза ниже
  однократного запуска.
- Не запускайте длинные серии бенчей подряд без перерывов на охлаждение.

---

## 6. Устранение неполадок

| Симптом | Причина | Решение |
|---|---|---|
| `failed to create context` | Флаг `-ctk q8_0` в CPU-only сборке | Убрать флаг `-ctk` |
| Очень низкий TG (< 1 tok/s) | Температурный throttle | Подождать 60 с, запустить снова с `-r 1` |
| Модель загружается, но генерация медленная | Большая MoE, активен mmap | Нормально; проверить `--run-time-repack auto: disabled` в логе |
| Кол-во потоков > 4 медленнее | Накладные расходы OpenMP sync на этом чипе | Оставить `-t 4` |
| Access violation при PP с большой MoE | MoE prefetch превышает RAM | Использовать короткие промпты; бенч PP512 невозможен для MoE > 14 ГБ |
